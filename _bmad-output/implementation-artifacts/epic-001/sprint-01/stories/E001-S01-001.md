# Add passphrase.encrypt_io / decrypt_io to pyrage

## Business acceptance criteria

### Outcome

pyrage exposes streaming passphrase encrypt/decrypt over file-like IO so multi-GB
archives never need to be buffered as `bytes`, and ciphertext decrypts with stock
`age -d`.

Spec: none — sourced from planning-artifacts/epics.md Story 1.1 / plan-4 Part A
(upstream woodruffw/pyrage; not this package's design-spec anchors).

### Non-goals

Does not publish a pyrage release to PyPI (Story 1.2). Does not change this package's
API. Does not alter existing one-shot `passphrase.encrypt` / `decrypt`.

## Technical acceptance criteria

### Interface contracts

Add `pyrage.passphrase.encrypt_io(reader, writer, passphrase, armored=False)` and
`decrypt_io(reader, writer, passphrase)` mirroring top-level `encrypt_io` /
`decrypt_io` (PyFileLikeObject + BufReader/BufWriter). Encrypt via
`Encryptor::with_user_passphrase`; decrypt via `scrypt::Identity`. Existing
`passphrase.encrypt` / `decrypt` signatures unchanged.

Spec: none — woodruffw/pyrage src/passphrase.rs; plan-4 Part A sketch.

### Error and edge case handling

Wrong passphrase → `DecryptError`. Truncated/damaged body fails in a mode distinct
from wrong passphrase so Python can map to CorruptDumpError later. Empty streams
round-trip. Multi-chunk readers (not only small `bytes`) succeed.

Spec: none — plan-4 Part A acceptance 1–4.

### Observability requirements

N/A — upstream library; no new logging contract in this package.

### Security considerations

Passphrase handled as rage `Secret`; must not appear in error strings returned to
Python. Output is age v1 with scrypt as sole recipient.

Spec: none — age format + plan-4 NFR2 for this package's later mapping.

### Testability approach

Unit/integration tests in the pyrage PR: multi-chunk round-trip; peak RSS flat on a
large synthetic reader; stock `age -d` recovers plaintext when `age` is available.

Spec: none — plan-4 Part A acceptance 1–3.

### Existing-library check

Uses rage's existing `Encryptor::with_user_passphrase` and `scrypt::Identity` —
no hand-rolled crypto. Pattern copies recipient `encrypt_io` / `decrypt_io` in
`lib.rs`.

Spec: none — woodruffw/pyrage already depends on rage.
