# CLI passphrase path without secret on argv

## Business acceptance criteria

### Outcome

Operators can dump/load with a passphrase via `--passphrase-file` or TTY prompt
without putting the secret on the argument vector; mutex with recipient/identity
flags.

Spec: none — epics.md Story 2.3 / plan-4 Part B CLI.

### Non-goals

Does not implement backup's AD-26 chain (lives in backup). Does not add
`--passphrase SECRET` on argv.

## Technical acceptance criteria

### Interface contracts

CLI flags: `--passphrase-file PATH` and/or interactive prompt for dump and load.
Mutex with `--recipient` / `--identity`. Pass resolved string into library
`passphrase=`. Update README examples; `tests/test_readme.py` must still parse.

Spec: none — plan-4 Part B CLI; design-spec §9 amend in Story 2.4.

### Error and edge case handling

Combined passphrase + recipient/identity → usage error (Exit.USAGE). Missing file →
clear InvalidArgumentsError / usage message without echoing secrets.

Spec: none — FR12; design-spec §9 exit codes.

### Observability requirements

Passphrase never in argv, logs, or help text examples as a literal secret.

Spec: none — design-spec §2.4.

### Security considerations

Never `--passphrase SECRET`. Prefer file or TTY; align with family secret rules.

Spec: none — plan-4 NFR2.

### Testability approach

Parser mutex tests; README parse guard; optional integration that dump with
passphrase-file produces age header.

Spec: none — plan-4 Part D / test_readme.

### Existing-library check

Uses Story 2.2 dump/load; no age CLI subprocess.

Spec: none — plan-4 rejected age-CLI path.
